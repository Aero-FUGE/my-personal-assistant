# 第二阶段：律的首页交互与本地任务指令

## 已实现

首页只有一个主要对话框。人物继续使用原始透明 PNG，原书房图片不变。默认显示最新一条助手消息；尚无对话时由真实首要任务、预计分钟和状态生成简短介绍。长回复可以展开阅读，不截断保存的数据。独立任务面板已从首页移除，排序选择器未改变。

“与律交谈”原地展开输入框；“安排事务”进入首页安排语境，不跳普通任务表单。“开始任务”复用既有状态切换与任务详情／编辑，不包含计时器。完整聊天页保留，二者使用同一份 conversations/messages 和同一个活动会话。原聊天记录不删除、不改写；旧版候选消息仍可确认，授权记忆和项目最近进展读取继续复用旧服务。

消息区向上滑或向下滚动鼠标滚轮会展开历史，也提供可点击入口。历史有独立限高滚动区、overscroll containment 和更早记录加载按钮，默认不会占满首页。输入在用户点击时同步聚焦，使用 VisualViewport 监听键盘遮挡，在需要时将输入区提升至键盘上方。自动化只模拟视口与手势，物理 iPhone 软键盘仍待真机验收。

## 任务执行的真实边界

当前是**本地确定性规则解析器，不是真实大模型**。没有 DeepSeek Key，也没有调用远程 AI。支持明确中文指令：

- 创建：明天下午两点安排写歌；明天下午帮我安排两个小时写歌（追问具体几点，回复“下午三点”后保存）。
- 修改：把刚才那个任务改到晚上八点；把任务改名为新名称（需明确目标）。
- 完成：把混音任务标记完成；完成写歌。
- 删除：删除整理资料任务 → 核对后确认执行或取消。
- 查询：今天／明天有什么安排；2026-11-12 有什么安排；今天最重要的事情是什么。

日期支持今天、明天、后天、明确 YYYY-MM-DD / 月日；时刻支持阿拉伯和中文数字、点、半、分及上午／下午／晚上。用时支持小时和分钟。只有表达匹配这些有限规则时才能执行；不声称能理解任意自然语言。下周、数小时后、刻钟等未支持的相对时间及夜间十二点的歧义会要求改用明确日期与时刻，不会悄悄排到今天。未指定日期和时间可以创建未排期任务；已指定日期／时段但缺少时刻时先追问。创建追问和“刚才那个任务”的上下文保存在该会话的 preferences 元数据中，刷新后仍可继续。修改缺少新时间时要求重新提供任务名称及明确时间，不是通用多轮推理。

普通创建和普通单项修改可直接提交；删除、时间冲突和高优先级修改必须确认。确认信息包含目标、拟变更时间／时长／名称和冲突事项。确认前后重新检查任务快照和新增冲突；数据有变动则中止并要求重新提出，不覆盖新数据。批量修改未实现，会明确拒绝并请用户逐项指定。否定、条件性表达、状态疑问和歧义目标不会擅自写库。

一次发送在 Dexie 事务内完成：保存用户消息 → 解析／校验 → 调用 TaskService → 保存上下文与真实操作结果。事务失败全部回滚，界面显示失败原因并保留输入，不产生虚假的“已保存”回复。消息请求 ID 防止重复提交，回复记录 affectedTaskIds。删除时同时清理 dailyPlans 关联，保留其他任务。任务与对话表结构及数据库版本均未改变；新增上下文使用现有 preferences 表的命名键，JSON 导入导出仍覆盖这些数据。

沿用现有模型的 dueAt 存放用户安排时刻；冲突按该时刻和预计分钟估算，不是外部日历预约或后台计时。TaskAction / TaskToolPlanner 为后续工具调用提供接口，原 BackendAIService 仍是未启用占位。未来真实模型请求必须在 IndexedDB 事务外完成，返回操作也必须重新验证、确认及落库，不能直接任意写数据库。

## 连续光影

room-light.ts 按浏览器现实本地时间，对 01:00、06:00、09:00、12:00、16:00、18:30、21:00 等关键帧做线性插值，跨午夜连续。分别计算背景亮度、饱和度、暖色、冷色、遮罩、窗边光晕和室内灯光。原始书房结构不变。CSS 光照只能模拟氛围，不能把原图窗外真正变成夜空，也没有添加新背景图。

进入首页立即计算目标，每约一分钟更新，CSS 60 秒过渡；隐藏时暂停光照计时，恢复或 pageshow 时重新同步；降动效偏好关闭过渡。没有逐帧 Canvas。人物仅轻微调整亮度（0.96–1.03），不扭曲五官、不压暗白衬衫或重绘眼镜。

## 角色状态

定义 gentle、focused、pleased、relaxed、shy，以及表情、动作和可选资源路径。进行中任务、完成、晚间和夸奖会改变逻辑状态。**当前没有新增表情素材，所有状态都显示原始 assistant-main.png**，不会请求虚构图片或用 CSS 扭曲脸部。正式同角色 PNG 到位后才能配置 image 字段。

## 字体与文案

六个主要页面及辅助页面的静态宣传语调整为律的克制、专业表达；必要功能名称、数据说明保留，用户标题、备注、项目名、历史消息不改动。全局建立标题／对话／正文／数字的语义字体栈和紫色文字／按钮基础变量，不重做其他页面布局。

最终字体已确认采用 **A 思源宋体**（以下保留候选对照）：

- A：思源宋体，优雅、克制；[官方来源与许可](https://github.com/adobe-fonts/source-han-serif)。
- B：霞鹜文楷，温柔、书写感；[官方来源与许可](https://github.com/lxgw/LxgwWenKai)。

预览地址 `#/font-preview`。[候选截图](./font-candidates.png) 使用真实 WOFF2 子集（约 43 KB + 23 KB），仅在预览页加载，并附原 OFL 文件。内部子集名称已独立命名，未把它们设为应用最终字体，也不将小样子集当完整中文覆盖。现已安装生产字体分包，保留原字体字符覆盖和系统回退；详见后续外观说明。
